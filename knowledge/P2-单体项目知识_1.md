## 1. 启动类的写法规则

```java
@SpringBootApplication
@MapperScan("org.example.monomer_seckill_backend.mapper")
public class MonomerSeckillBackendApplication {
    public static void main(String[] args) {
        SpringApplication.run(MonomerSeckillBackendApplication.class, args);
    }
}
```

### 1.1 `@SpringBootApplication` 注解

这是 Spring Boot 的核心组合注解，等价于同时使用三个注解：

| 组成注解 | 作用 |
|---------|------|
| `@SpringBootConfiguration` | 标识这是一个配置类，等价于 `@Configuration` |
| `@EnableAutoConfiguration` | 启用 Spring Boot 的自动配置机制（根据 classpath 下的依赖自动装配 Bean） |
| `@ComponentScan` | 自动扫描当前包及子包下的 Spring 组件（`@Controller`、`@Service`、`@Repository` 等） |

**设计理念**：Spring Boot 的"约定优于配置"，一个注解完成过去需要大量 XML 配置才能完成的工作。

### 1.2 `@MapperScan` 注解

用于扫描指定包下的所有 Mapper 接口，并将它们注册为 Spring Bean。

**为什么写在启动类上？**
- 只需写一次，新增 Mapper 无需改动代码
- 统一管理 Mapper 层位置，启动类一目了然
- 符合分层架构设计

**如果不写会怎样？**
- Mapper 接口不会被 Spring 容器管理
- 注入时会报错：`No qualifying bean of type 'xxxMapper'`

### 1.3 `@MapperScan` vs `@Mapper` 对比

| 对比项 | `@MapperScan`（启动类上写一次） | `@Mapper`（每个接口上写） |
|--------|-------------------------------|--------------------------|
| 代码量 | 只需写一次 | 每个 Mapper 都要写 |
| 维护性 | 新增 Mapper 无需改动 | 容易忘记添加注解 |
| 性能 | 略优（批量扫描指定包） | 略差（扫描整个 classpath） |
| 灵活性 | 统一管理，不够灵活 | 可以精确控制每个 Mapper |
| 可读性 | 启动类一目了然 | 需要打开每个 Mapper 才知道 |

> 性能差异在毫秒级，实际项目中可忽略。推荐使用 `@MapperScan`，维护成本更低。

### 1.4 `@MapperScan` 的来源

`@MapperScan` 有两个来源：

| 来源 | 包路径 | 说明 |
|------|--------|------|
| MyBatis 原生 | `org.apache.ibatis.annotations.MapperScan` | 需引入 `mybatis-spring-boot-starter` |
| MyBatis-Plus 扩展 | `com.baomidou.mybatisplus.core.mapper.annotation.MapperScan` | 功能更强大，需引入 MP 依赖 |

本项目引入了 `mybatis-plus-spring-boot3-starter`，它会自动传递引入 MyBatis 核心依赖，因此两个来源的 `@MapperScan` 都可以使用。

> 如果没有引入 MyBatis 或 MyBatis-Plus 的任何依赖，则不能使用 `@MapperScan`，也不能使用 `@Mapper`。

## 2. `SpringApplication.run()` 的作用

```java
SpringApplication.run(MonomerSeckillBackendApplication.class, args);
```

**不是"启动自己这个类"，而是"启动以这个类为入口的 Spring 容器"。**

### 执行流程

```
1. 创建 SpringApplication 对象
   └── 以 MonomerSeckillBackendApplication.class 作为主配置类

2. 推断应用类型（Servlet / Reactive）
   └── 检测到 spring-boot-starter-web → Servlet 应用

3. 加载所有配置源
   ├── @SpringBootApplication 注解
   ├── application.yml 配置文件
   ├── 命令行参数 args
   └── 环境变量

4. 启动 Spring 容器
   ├── 创建 ApplicationContext
   ├── 执行自动配置（@EnableAutoConfiguration）
   ├── 扫描组件（@ComponentScan）
   └── 初始化所有 Bean

5. 启动内嵌 Tomcat
   └── 监听端口（默认 8080）
```

### 为什么传入自己的 Class？

- 这个类上有 `@SpringBootApplication` 注解
- Spring 会以这个类的包路径为基准，扫描当前包及子包下的所有组件
- 相当于告诉 Spring："从这个类开始，加载整个应用"

## 3. `args` 参数：jar 包启动时的命令行参数

```java
public static void main(String[] args) {
    SpringApplication.run(MonomerSeckillBackendApplication.class, args);
}
```

`args` 就是启动 jar 包时在命令行后面配置的参数：

```bash
java -jar app.jar --server.port=8081 --spring.profiles.active=prod
```

Spring 会解析成：
- `server.port=8081`
- `spring.profiles.active=prod`

### 配置加载优先级（从高到低）

```
1. 命令行参数 args
   └── java -jar app.jar --server.port=8081

2. Java 系统属性
   └── -Dserver.port=8081

3. 环境变量
   └── SERVER_PORT=8081

4. application-{profile}.yml（指定环境配置）
   └── application-prod.yml

5. application.yml（默认配置）
   └── server.port: 8080

6. 默认值
   └── Spring Boot 内置默认值
```

**核心机制**：启动程序的过程中会合并命令行参数和 `application.yml` 中的配置，高优先级覆盖低优先级。

## 4. Spring Boot 默认从哪些位置扫描配置文件

### 4.1 配置文件名称约定

Spring Boot 默认查找名为 `application` 的配置文件，支持以下格式：
- `application.yml` / `application.yaml`（推荐）
- `application.properties`
- `application.json`

**这是硬编码在 Spring Boot 源码中的默认行为。**

### 4.2 扫描位置（优先级从高到低）

| 优先级 | 位置 | 说明 |
|--------|------|------|
| 1 | `file:./config/` | jar 包所在目录的 `config` 子目录 |
| 2 | `file:./` | jar 包所在目录 |
| 3 | `classpath:/config/` | classpath 的 `config` 包下 |
| 4 | `classpath:/` | classpath 根目录（**最常用**） |

### 4.3 classpath 是什么？

**classpath 不是文件系统的"当前目录"，而是 Java 程序运行时的"类路径"。**

Maven 项目的构建过程：

```
开发时的项目结构：
src/main/java/         → Java 源代码
src/main/resources/    → 资源文件（application.yml 等）

编译后（Maven 构建）：
src/main/java/         → 编译为 .class → target/classes/
src/main/resources/    → 直接复制      → target/classes/
```

**`target/classes/` 就是 classpath 根目录！** 所以 `src/main/resources/application.yml` 编译后会被复制到 `target/classes/application.yml`，Spring Boot 在 classpath 根目录找到它。

### 4.4 打包成 jar 后的结构

```
monomer_seckill_backend.jar
├── BOOT-INF/
│   ├── classes/              ← classpath 根目录
│   │   ├── org/example/...   ← 编译后的 .class 文件
│   │   └── application.yml   ← 配置文件
│   └── lib/                  ← 依赖的 jar 包
├── META-INF/
│   └── MANIFEST.MF
└── org/springframework/boot/loader/  ← Spring Boot 启动器
```

运行 `java -jar app.jar` 时，Spring Boot 设置 classpath = `BOOT-INF/classes/`，在 classpath 下查找 `application.yml`。

### 4.5 为什么扫描 classpath 而不是文件系统目录？

classpath 是唯一在**所有环境**下都存在的"统一路径"：
- ✅ 开发环境：在 IDE 中运行（classpath = `target/classes`）
- ✅ 测试环境：运行单元测试（classpath = `target/test-classes`）
- ✅ 生产环境：打包成 jar 运行（classpath = jar 包内部 `BOOT-INF/classes/`）

### 4.6 默认配置可以修改吗？

**可以！** 通过以下方式修改默认配置文件名称或位置：

```bash
# 修改配置文件名称（默认查找 myconfig.yml 而非 application.yml）
java -jar app.jar --spring.config.name=myconfig

# 指定完整配置文件路径
java -jar app.jar --spring.config.location=classpath:/custom-config.yml

# 追加配置文件路径（不覆盖默认）
java -jar app.jar --spring.config.additional-location=classpath:/custom/
```

## 5. 如何本地和线上使用两套配置

### 5.1 方案一：多 Profile 文件（推荐）

创建多个配置文件：

```
src/main/resources/
├── application.yml              # 公共配置（所有环境共享）
├── application-dev.yml          # 开发环境配置
├── application-prod.yml         # 生产环境配置
└── application-test.yml         # 测试环境配置
```

**application.yml（公共配置）**
```yaml
server:
  port: 7099

spring:
  application:
    name: monomer-seckill-backend
  profiles:
    active: dev  # 默认激活开发环境

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
```

**application-dev.yml（本地开发）**
```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3307/monomer_seckill
    username: root
    password: 123456hy
  data:
    redis:
      host: localhost
      port: 6379

logging:
  level:
    org.example.monomer_seckill_backend: debug
```

**application-prod.yml（生产环境）**
```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:3306/monomer_seckill
    username: ${DB_USER:root}
    password: ${DB_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: 6379

logging:
  level:
    org.example.monomer_seckill_backend: info
```

### 5.2 激活指定 Profile

```bash
# 方式一：命令行参数
java -jar app.jar --spring.profiles.active=prod

# 方式二：环境变量
export SPRING_PROFILES_ACTIVE=prod
java -jar app.jar

# 方式三：在 application.yml 中指定（默认）
spring:
  profiles:
    active: dev
```

### 5.3 方案二：单文件多 Profile（适合简单项目）

在同一个 `application.yml` 中使用 `---` 分隔：

```yaml
# 公共配置
server:
  port: 7099

spring:
  application:
    name: monomer-seckill-backend

---
# 开发环境
spring:
  config:
    activate:
      on-profile: dev
  datasource:
    url: jdbc:mysql://localhost:3307/monomer_seckill
    username: root
    password: 123456hy

---
# 生产环境
spring:
  config:
    activate:
      on-profile: prod
  datasource:
    url: jdbc:mysql://${DB_HOST}:3306/monomer_seckill
    username: ${DB_USER}
    password: ${DB_PASSWORD}
```

### 5.4 敏感信息处理

生产环境的密码等敏感信息**不要硬编码在配置文件中**，使用环境变量占位符：

```yaml
password: ${DB_PASSWORD}  # 从环境变量读取
```

```bash
# 启动时通过环境变量注入
export DB_PASSWORD=secure_password
java -jar app.jar --spring.profiles.active=prod
```

## 6. 依赖注入：构造器注入 vs `@Autowired` 字段注入 vs `@Resource` 字段注入

### 6.1 三种注入方式对比

#### 构造器注入（Spring 官方推荐 ✅）

```java
@RestController
public class GoodsController {
    private final GoodsService goodsService;

    public GoodsController(GoodsService goodsService) {
        this.goodsService = goodsService;
    }
}
```

> Spring 4.3+ 单构造方法可省略 `@Autowired`，Spring 会自动注入。

#### `@Autowired` 字段注入（不推荐 ❌）

```java
@RestController
public class GoodsController {
    @Autowired
    private GoodsService goodsService;  // 不能用 final
}
```

#### `@Resource` 字段注入（不推荐 ❌）

```java
@RestController
public class GoodsController {
    @Resource
    private GoodsService goodsService;  // 不能用 final
}
```

### 6.2 `@Autowired` vs `@Resource` 对比

| 特性 | `@Autowired` | `@Resource` |
|------|-------------|-------------|
| 来源 | Spring 框架注解 | Java 标准注解（JSR-250） |
| 默认注入方式 | 按类型（byType） | 按名称（byName） |
| 字段注入 | ✅ 支持 | ✅ 支持 |
| Setter 注入 | ✅ 支持 | ✅ 支持 |
| 构造器注入 | ✅ 支持（单构造可省略） | ❌ **不支持** |
| 可搭配 `@Qualifier` | ✅ 可以 | ❌ 不需要（自带 name 属性） |

### 6.3 三种方式全面对比

| 特性 | 构造器注入 | `@Autowired` 字段注入 | `@Resource` 字段注入 |
|------|-----------|----------------------|---------------------|
| 能否使用 `final` | ✅ 可以（线程安全） | ❌ 不可以 | ❌ 不可以 |
| 依赖关系明确性 | ✅ 一目了然 | ❌ 隐藏在类内部 | ❌ 隐藏在类内部 |
| 空指针风险 | ✅ 无（编译期检查） | ❌ 有（运行时才发现） | ❌ 有（运行时才发现） |
| 单元测试 | ✅ 直接 `new` 传入 Mock | ❌ 需要反射 | ❌ 需要反射 |
| Spring 官方推荐 | ✅ 推荐 | ❌ 不推荐 | ❌ 不推荐 |

### 6.4 为什么构造器注入方便单元测试

**构造器注入：直接 new 传入 Mock 对象**

```java
@Test
void testList() {
    // 1. 创建 Mock 对象（假的 GoodsService，不连接数据库）
    GoodsService mockService = Mockito.mock(GoodsService.class);
    // 2. 定义 Mock 行为（当调用 list() 时返回预设数据）
    Mockito.when(mockService.list()).thenReturn(List.of(new Goods()));
    // 3. 直接通过构造方法传入 Mock
    GoodsController controller = new GoodsController(mockService);
    // 4. 调用方法
    Result<List<Goods>> result = controller.list();
    // 5. 验证结果
    Assertions.assertNotNull(result);
    Assertions.assertEquals(1, result.getData().size());
}
```

**不需要启动 Spring 容器、不需要连接数据库、不需要连接 Redis，执行速度毫秒级。**

### 6.5 字段注入时如何进行单元测试

字段注入没有带参数的构造方法，且字段是私有的，不能直接 `new` 传入 Mock，必须通过反射设置。

#### 方式一：使用 `ReflectionTestUtils`（Spring 测试工具）

```java
@Test
void testList() {
    GoodsService mockService = Mockito.mock(GoodsService.class);
    Mockito.when(mockService.list()).thenReturn(List.of(new Goods()));

    GoodsController controller = new GoodsController();  // 无参构造，goodsService = null

    // 使用反射设置私有字段
    ReflectionTestUtils.setField(controller, "goodsService", mockService);

    Result<List<Goods>> result = controller.list();
    Assertions.assertNotNull(result);
}
```

`ReflectionTestUtils.setField()` 等价于：
```java
Field field = GoodsController.class.getDeclaredField("goodsService");
field.setAccessible(true);  // 突破 private 限制
field.set(controller, mockService);
```

#### 方式二：使用 `@InjectMocks`（Mockito 注解，推荐）

```java
class GoodsControllerTest {
    @Mock
    private GoodsService mockService;  // Mockito 创建 Mock 对象

    @InjectMocks
    private GoodsController controller;  // 自动将 Mock 注入到 Controller 的字段

    @BeforeEach
    void setUp() {
        MockitoAnnotations.openMocks(this);  // 初始化 Mockito 注解
    }

    @Test
    void testList() {
        Mockito.when(mockService.list()).thenReturn(List.of(new Goods()));
        Result<List<Goods>> result = controller.list();
        Assertions.assertEquals(1, result.getData().size());
    }
}
```

`@InjectMocks` 工作原理：扫描目标类的所有字段 → 找到类型匹配的字段 → 使用反射注入 Mock 对象。

#### 方式三：使用 `@SpringBootTest`（集成测试，重量级）

```java
@SpringBootTest  // 启动完整的 Spring 容器
class GoodsControllerTest {
    @MockBean  // Spring Boot 提供，替换容器中的真实 Bean 为 Mock
    private GoodsService mockService;

    @Autowired  // Spring 自动注入 Controller
    private GoodsController controller;

    @Test
    void testList() {
        Mockito.when(mockService.list()).thenReturn(List.of(new Goods()));
        Result<List<Goods>> result = controller.list();
        Assertions.assertEquals(1, result.getData().size());
    }
}
```

| 方案 | 适用场景 | 速度 | 依赖 |
|------|---------|------|------|
| `ReflectionTestUtils` | 快速单元测试 | 快 | Spring Test |
| `@InjectMocks` | 单元测试（推荐） | 快 | Mockito |
| `@SpringBootTest` | 集成测试 | 慢（秒级） | 完整 Spring 容器 |

### 6.6 单元测试中 Mock 的作用

**Mock = 创建一个"假对象"，模拟真实行为，不依赖外部环境。**

| 对比 | 真实对象 | Mock 对象 |
|------|---------|----------|
| 数据库 | 真实查询数据库 | 返回预设的假数据 |
| Redis | 真实连接 Redis | 返回预设的假数据 |
| 速度 | 慢（网络 I/O） | 极快（内存操作） |
| 依赖 | 需要完整环境 | 无需任何外部依赖 |

单元测试的核心价值：**隔离测试单个类/方法的逻辑，不依赖数据库、Redis 等外部环境。**

## 7. 补充：Mockito 的 Java Agent 警告

使用 Mockito 创建 Mock 对象时，JDK 21 可能输出以下警告：

```
WARNING: A Java agent has been loaded dynamically (byte-buddy-agent-xxx.jar)
WARNING: If a serviceability tool is in use, please run with -XX:+EnableDynamicAgentLoading to hide this warning
WARNING: Dynamic loading of agents will be disallowed by default in a future release
```

### 原因

- Mockito 使用 **Byte Buddy** 库动态修改类的字节码来创建 Mock 对象
- JDK 21 引入了新的安全限制：动态加载 Java Agent 被认为不安全，未来版本将默认禁止
- 这是**预告性警告**，不影响测试执行

### 解决方案

| 方案 | 操作 | 推荐度 |
|------|------|--------|
| 忽略警告 | 测试通过即可，安全忽略 | ✅ 推荐 |
| 添加 JVM 参数 | `-XX:+EnableDynamicAgentLoading` | 可选 |
| Maven 配置 | `maven-surefire-plugin` 中配置 `argLine` | 可选 |
| 升级 Mockito | 使用最新版本（5.12+） | 可选 |

Maven 配置示例：
```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-surefire-plugin</artifactId>
    <configuration>
        <argLine>-XX:+EnableDynamicAgentLoading</argLine>
    </configuration>
</plugin>
```
