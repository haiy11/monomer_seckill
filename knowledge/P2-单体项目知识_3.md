## 1. MyBatis 操作数据库的两种方式

MyBatis 提供了两种操作数据库的方式，MyBatis-Plus 完全兼容这两种方式。

### 1.1 方式一：注解方式（@Select / @Insert / @Update / @Delete）

在 Mapper 接口方法上直接编写 SQL 语句，无需 XML 文件。

```java
public interface UserMapper extends BaseMapper<User> {

    // 查询
    @Select("SELECT * FROM mall_user WHERE id = #{id}")
    User selectById(Long id);

    @Select("SELECT COUNT(*) FROM mall_user WHERE role = #{role}")
    Long countByRole(@Param("role") Integer role);

    // 插入
    @Insert("INSERT INTO mall_user(username, password, nickname) VALUES(#{username}, #{password}, #{nickname})")
    @Options(useGeneratedKeys = true, keyProperty = "id")  // 返回自增主键
    int insertAndGetId(User user);

    // 更新
    @Update("UPDATE mall_user SET nickname = #{nickname}, phone = #{phone} WHERE id = #{id}")
    int updateById(User user);

    // 删除
    @Delete("DELETE FROM mall_user WHERE id = #{id}")
    int deleteById(Long id);
}
```

**适用场景**：简单、固定的 SQL（1-3 行），不需要动态条件。

### 1.2 方式二：XML 映射文件

将 SQL 写在单独的 XML 文件中，支持动态 SQL 标签。

**UserMapper.xml：**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="org.example.monomer_seckill_backend.user.mapper.UserMapper">

    <!-- 复杂条件查询用户 -->
    <select id="complexQueryUsers" resultType="org.example.monomer_seckill_backend.user.entity.User">
        SELECT * FROM mall_user
        <where>
            <if test="username != null and username != ''">
                AND username LIKE CONCAT('%', #{username}, '%')
            </if>
            <if test="role != null">
                AND role = #{role}
            </if>
            <if test="startTime != null">
                AND create_time &gt;= #{startTime}
            </if>
            <if test="endTime != null">
                AND create_time &lt;= #{endTime}
            </if>
            <if test="roles != null and roles.size() > 0">
                AND role IN
                <foreach collection="roles" item="role" open="(" separator="," close=")">
                    #{role}
                </foreach>
            </if>
        </where>
        ORDER BY create_time DESC
    </select>

    <!-- 多表关联查询 -->
    <select id="findUserOrderStats" resultType="org.example.monomer_seckill_backend.user.vo.UserOrderStatVO">
        SELECT u.id, u.username, u.nickname, u.role,
               COUNT(o.id) as orderCount,
               COALESCE(SUM(o.total_amount), 0) as totalAmount,
               MAX(o.create_time) as lastOrderTime
        FROM mall_user u
        LEFT JOIN orders o ON u.id = o.user_id
        WHERE u.role = #{role}
        GROUP BY u.id
        ORDER BY orderCount DESC
    </select>
</mapper>
```

**UserMapper.java 中声明对应方法：**
```java
List<User> complexQueryUsers(@Param("username") String username,
                              @Param("role") Integer role,
                              @Param("startTime") LocalDateTime startTime,
                              @Param("endTime") LocalDateTime endTime,
                              @Param("roles") List<Integer> roles,
                              @Param("limit") Integer limit);

List<UserOrderStatVO> findUserOrderStats(@Param("role") Integer role);
```

**适用场景**：复杂 SQL（多表关联、子查询）、需要动态条件（`<if>、<foreach>、<where>` 等标签）。

## 2. 注解方式与 XML 方式的对比

### 2.1 核心对比

| 特性 | 注解方式 | XML 方式 |
|------|---------|---------|
| **SQL 位置** | 直接写在 Mapper 接口方法上 | 写在单独的 XML 文件中 |
| **简洁性** | ✅ SQL 与方法一目了然 | ❌ 需要在文件间跳转 |
| **复杂 SQL** | ❌ 不适合（可读性差） | ✅ 适合（格式清晰） |
| **动态 SQL** | ❌ 需配合 `@SelectProvider` | ✅ 支持 `<if>、<foreach>、<where>` 等标签 |
| **维护性** | ✅ 简单 SQL 维护方便 | ✅ 复杂 SQL 维护方便 |
| **团队协作** | 适合小型项目 | 适合大型项目 |
| **结果映射** | 使用 `@Results` 注解 | 使用 `<resultMap>` 标签 |

### 2.2 选择策略

```
SQL 复杂度低（1-3 行，固定条件）
    → 使用 @Select 注解

SQL 复杂度高（多表关联、子查询、动态条件）
    → 使用 XML 映射文件
```

### 2.3 注解方式的高级用法

#### 动态 SQL（@SelectProvider）

当注解方式需要动态 SQL 时，可以使用 `@SelectProvider`：

```java
// SQL 提供类
public class UserSqlProvider {
    public String queryUsers(Map<String, Object> params) {
        return new SQL() {{
            SELECT("*");
            FROM("mall_user");
            if (params.get("username") != null) {
                WHERE("username LIKE CONCAT('%', #{username}, '%')");
            }
            if (params.get("role") != null) {
                WHERE("role = #{role}");
            }
            ORDER_BY("create_time DESC");
        }}.toString();
    }
}

// Mapper 中使用
@SelectProvider(type = UserSqlProvider.class, method = "queryUsers")
List<User> queryUsers(Map<String, Object> params);
```

#### 结果映射（@Results）

当数据库字段名与实体类属性名不一致时：

```java
@Select("SELECT user_name, user_phone FROM mall_user WHERE id = #{id}")
@Results({
    @Result(property = "username", column = "user_name"),
    @Result(property = "phone", column = "user_phone")
})
User selectById(Long id);
```

#### 关联查询（@Many / @One）

```java
// 一对多：用户关联订单列表
@Select("SELECT * FROM mall_user WHERE id = #{id}")
@Results({
    @Result(property = "id", column = "id"),
    @Result(property = "orders", column = "id",
            many = @Many(select = "org.example.mapper.OrderMapper.selectByUserId"))
})
User selectUserWithOrders(Long id);
```

## 3. MyBatis-Plus 独有的增强查询方法

MyBatis-Plus 的定位是 **"只做增强不做改变"**：完全兼容 MyBatis 的所有功能（注解、XML），同时提供以下独有增强。

### 3.1 BaseMapper（通用 Mapper）

继承 `BaseMapper<T>` 后，自动拥有 17+ 个常用方法，无需手写：

```java
public interface UserMapper extends BaseMapper<User> {
    // 自动拥有：
    // - insert(T entity)
    // - updateById(T entity)
    // - deleteById(Serializable id)
    // - delete(Wrapper<T> queryWrapper)
    // - selectById(Serializable id)
    // - selectList(Wrapper<T> queryWrapper)
    // - selectPage(Page<T> page, Wrapper<T> queryWrapper)
    // - selectCount(Wrapper<T> queryWrapper)
    // ... 等
}
```

| 对比项 | 原生 MyBatis | MyBatis-Plus |
|--------|-------------|--------------|
| **Mapper 方法** | 必须手动定义所有方法 | 继承 `BaseMapper` 自动拥有 |
| **insert** | 手写 `@Insert` 或 XML | 自动拥有 |
| **updateById** | 手写 `@Update` 或 XML | 自动拥有 |
| **deleteById** | 手写 `@Delete` 或 XML | 自动拥有 |
| **selectById** | 手写 `@Select` 或 XML | 自动拥有 |
| **selectList** | 手写 `@Select` 或 XML | 自动拥有 |
| **selectPage** | 需自己实现或用 PageHelper | 自动拥有（配合分页插件） |

### 3.2 QueryWrapper / LambdaQueryWrapper（动态构建查询条件）

这是 MyBatis-Plus 的核心特性，原生 MyBatis **没有**此功能。在 Service 层动态构建查询条件，无需写 SQL。

#### 基本用法：多条件动态查询 + 分页

```java
public IPage<User> queryUsers(String username, Integer role, String phone,
                               LocalDateTime startTime, LocalDateTime endTime,
                               int pageNum, int pageSize) {
    LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<>();

    // 动态条件拼接（只有参数不为空时才添加条件）
    queryWrapper
        .like(StringUtils.isNotBlank(username), User::getUsername, username)  // 模糊查询
        .eq(role != null, User::getRole, role)                                // 精确匹配
        .like(StringUtils.isNotBlank(phone), User::getPhone, phone)
        .between(startTime != null && endTime != null,
                 User::getCreateTime, startTime, endTime)                     // 范围查询
        .orderByDesc(User::getCreateTime);                                    // 排序

    // 创建分页对象
    Page<User> page = new Page<>(pageNum, pageSize);

    return userMapper.selectPage(page, queryWrapper);
}
```

#### 高级用法：嵌套条件、IN 查询、分组查询

```java
public List<User> complexQuery(String username, List<Integer> roles, Boolean hasPhone) {
    LambdaQueryWrapper<User> queryWrapper = new LambdaQueryWrapper<>();

    // 用户名模糊查询
    if (StringUtils.isNotBlank(username)) {
        queryWrapper.like(User::getUsername, username);
    }

    // 角色在指定列表中
    if (roles != null && !roles.isEmpty()) {
        queryWrapper.in(User::getRole, roles);
    }

    // 是否填写了手机号
    if (hasPhone != null) {
        if (hasPhone) {
            queryWrapper.isNotNull(User::getPhone).ne(User::getPhone, "");
        } else {
            queryWrapper.and(wrapper -> wrapper
                .isNull(User::getPhone)
                .or()
                .eq(User::getPhone, "")
            );
        }
    }

    // 嵌套条件：(角色=1 或 角色=2) 且 创建时间在最近30天
    queryWrapper.and(wrapper -> wrapper
        .eq(User::getRole, 1)
        .or()
        .eq(User::getRole, 2)
    ).ge(User::getCreateTime, LocalDateTime.now().minusDays(30));

    return userMapper.selectList(queryWrapper);
}
```

#### QueryWrapper 常用方法一览

| 方法 | 对应 SQL | 说明 |
|------|---------|------|
| `.eq(field, value)` | `= value` | 精确匹配 |
| `.ne(field, value)` | `!= value` | 不等于 |
| `.gt(field, value)` | `> value` | 大于 |
| `.ge(field, value)` | `>= value` | 大于等于 |
| `.lt(field, value)` | `< value` | 小于 |
| `.le(field, value)` | `<= value` | 小于等于 |
| `.like(field, value)` | `LIKE '%value%'` | 模糊查询 |
| `.likeLeft(field, value)` | `LIKE '%value'` | 左模糊 |
| `.likeRight(field, value)` | `LIKE 'value%'` | 右模糊 |
| `.in(field, list)` | `IN (...)` | IN 查询 |
| `.notIn(field, list)` | `NOT IN (...)` | NOT IN 查询 |
| `.isNull(field)` | `IS NULL` | 为空 |
| `.isNotNull(field)` | `IS NOT NULL` | 不为空 |
| `.between(field, v1, v2)` | `BETWEEN v1 AND v2` | 范围查询 |
| `.orderByDesc(field)` | `ORDER BY field DESC` | 降序排序 |
| `.orderByAsc(field)` | `ORDER BY field ASC` | 升序排序 |
| `.groupBy(field)` | `GROUP BY field` | 分组 |
| `.having(sql, params)` | `HAVING ...` | 分组后过滤 |
| `.and(consumer)` | `AND (...)` | 嵌套 AND |
| `.or(consumer)` | `OR (...)` | 嵌套 OR |

> **条件构造器方法的三参数版本**：第一个参数为 `boolean` 类型，为 `true` 时才拼接该条件，实现动态查询。
> 例如：`.eq(role != null, User::getRole, role)` 只有 `role != null` 时才添加 `role = ?` 条件。

### 3.4 其他增强功能

| 功能 | 原生 MyBatis | MyBatis-Plus |
|------|-------------|--------------|
| **自动分页** | ❌ 需自己实现或用 PageHelper | ✅ 内置 `PaginationInnerInterceptor` |
| **逻辑删除** | ❌ 需手写 SQL | ✅ `@TableLogic` 注解 |
| **自动填充** | ❌ 需手写 | ✅ `@TableField(fill = FieldFill.INSERT)` |
| **乐观锁** | ❌ 需手写 | ✅ `@Version` 注解 |
| **代码生成器** | ❌ 无 | ✅ 内置 |

#### 逻辑删除

```java
@TableLogic  // 标记为逻辑删除字段
private Integer deleted;  // 0-未删除, 1-已删除
```

配置后，`deleteById` 会执行 `UPDATE ... SET deleted = 1`，查询自动过滤 `deleted = 0`。

#### 自动填充

```java
@TableField(fill = FieldFill.INSERT)       // 插入时自动填充
private LocalDateTime createTime;

@TableField(fill = FieldFill.INSERT_UPDATE) // 插入和更新时自动填充
private LocalDateTime updateTime;
```

#### 乐观锁

```java
@Version  // 标记为乐观锁字段
private Integer version;
```

更新时自动执行 `UPDATE ... SET version = version + 1 WHERE version = #{version}`。

## 4. MyBatis-Plus 代码生成器

### 4.1 代码生成器的作用

MyBatis-Plus 提供了强大的代码生成器，可以根据数据库表结构**自动生成标准代码**，开发者无需手写：

- **Entity 实体类**（包含字段映射、Lombok 注解、Swagger 注解等）
- **Mapper 接口**（继承 `BaseMapper`，无需手写方法）
- **Mapper XML 文件**（基础结构，预留自定义 SQL 的位置）
- **Service 接口**（继承 `IService`）
- **Service 实现类**（继承 `ServiceImpl`，包含 `@Service` 注解）
- **Controller 类**（包含 `@RestController`、基础 RESTful 接口）

### 4.2 代码生成器的意义

| 问题 | 不用生成器 | 用生成器 |
|------|-----------|---------|
| **Entity 类** | 手动创建字段、getter/setter、注解 | 自动生成 |
| **Mapper 接口** | 手动继承 BaseMapper、手写方法 | 自动继承 BaseMapper |
| **Mapper XML** | 手动创建文件、命名空间 | 自动生成基础结构 |
| **Service 层** | 手动创建接口和实现类 | 自动生成 |
| **Controller** | 手动创建 RESTful 接口 | 自动生成 |
| **开发效率** | 每张表 30+ 分钟 | 每张表几秒 |

### 4.3 生成器生成的标准代码结构

以 `user` 表为例，生成器会自动生成以下文件：

```
org.example.monomer_seckill_backend.user
├── controller/
│   └── UserController.java          // @RestController，包含增删改查接口
├── entity/
│   └── User.java                    // @Data + @TableName，字段映射
├── mapper/
│   └── UserMapper.java              // extends BaseMapper<User>
├── service/
│   ├── UserService.java             // extends IService<User>
│   └── impl/
│       └── UserServiceImpl.java     // extends ServiceImpl<UserMapper, User>
└── vo/
    └── UserVo.java                  // 视图对象（如配置）
```

**生成的 Entity 示例：**
```java
@Data
@TableName("mall_user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String username;
    private String password;
    private String nickname;
    private Integer role;
    private String phone;
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;
    @TableLogic
    private Integer deleted;
}
```

**生成的 Mapper 示例：**
```java
public interface UserMapper extends BaseMapper<User> {
    // 继承 BaseMapper，自动拥有 17+ 个方法
    // 如需自定义复杂查询，在此添加方法
}
```

**生成的 Service 示例：**
```java
public interface UserService extends IService<User> {
    // 继承 IService，自动拥有更多便捷方法
}

@Service
public class UserServiceImpl extends ServiceImpl<UserMapper, User> implements UserService {
    // 继承 ServiceImpl，自动实现 IService 的所有方法
}
```

### 4.4 生成器与手写的关系

代码生成器生成的是**标准模板代码**，开发者在此基础上进行业务定制：

```
代码生成器生成标准代码
    ↓
开发者在此基础上：
    1. Entity：添加业务字段、注解
    2. Mapper：添加自定义复杂查询方法（@Select 或 XML）
    3. Service：添加业务逻辑方法
    4. Controller：添加业务接口
```

> **关键理解**：生成器生成的是"骨架"，开发者填充"血肉"。标准 CRUD 不需要手写，复杂查询在此基础上添加。

## 6. MyBatis-Plus 的定位总结

```
MyBatis-Plus = MyBatis（完全兼容） + 增强工具（独有）

MyBatis 的能力（MyBatis-Plus 完全继承）：
    ├── 注解方式（@Select / @Insert / @Update / @Delete）
    └── XML 映射文件（支持动态 SQL）

MyBatis-Plus 的增强（MyBatis 没有）：
    ├── BaseMapper（通用 Mapper，17+ 方法免手写）
    ├── QueryWrapper / LambdaQueryWrapper（动态构建查询条件）
    ├── IService / ServiceImpl（Service 层增强）
    ├── 自动分页（PaginationInnerInterceptor）
    ├── 逻辑删除（@TableLogic）
    ├── 自动填充（@TableField(fill = ...)）
    ├── 乐观锁（@Version）
    └── 代码生成器（自动生成 Entity/Mapper/Service/Controller）
```

> **核心原则**：MyBatis-Plus "只做增强不做改变"。它不会替代 MyBatis 的任何功能，而是在 MyBatis 的基础上提供更多便捷特性，减少重复代码，提升开发效率。
